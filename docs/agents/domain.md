# Domain Docs

## Before exploring

Read root `CONTEXT.md` and any relevant `docs/adr/` files when they exist. If neither exists, proceed without calling out their absence. The repository is single-context: future domain documentation belongs at the root, with architecture decisions in `docs/adr/`.

## Consumer rules

Use terms defined in `CONTEXT.md` for issue titles, proposals, tests, and code. If a needed concept is absent, either avoid inventing a synonym or record the gap for domain modeling. Surface any conflict with an existing ADR rather than silently overriding it.
